# Local development and demo environment — VrtićOS

- Version: 0.1 · Date: 2026-11-10 · Phase: 3 · Decision: ADR-0009
- Goal: any developer (or the owner before a kindergarten presentation) runs the **whole system** on one machine with
  synthetic data — no cloud account, no paid service, no production data.

## 2. Prerequisites (developer machine)
- Docker-compatible runtime with ≥ 8 GB RAM and ~10 GB free disk for images.
- Node.js 22 LTS; pnpm via Corepack (version pinned in root `package.json` → `packageManager`).
- For mobile: Expo Go on a phone (iOS/Android) on the same Wi-Fi, or Android Studio emulator; Xcode simulator on macOS.
- Optional: an authenticator app (TOTP) for manager MFA in the demo.
- Not needed: Supabase account, Vercel account, Expo account, Sentry, any email provider.

## 3. Services and ports (Supabase defaults)
| Service | URL | Purpose |
|---|---|---|
| API gateway (PostgREST, Auth, Storage, Functions) | `http://127.0.0.1:54321` | clients connect here |
| Postgres | `postgresql://postgres:postgres@127.0.0.1:54322/postgres` | migrations, pgTAP, psql |
| Studio | `http://127.0.0.1:54323` | optional DB browser |
| Mailpit | `http://127.0.0.1:54324` | catches all auth/invitation emails locally — **no email leaves the machine** |
| Admin (Next.js) | `http://localhost:3000` | |
| Expo dev server | `exp://<LAN-IP>:8081` | mobile |

The keys printed by `supabase start` are the **public, well-known local development keys** — not secrets, valid only
for the local stack. Never reuse them anywhere else; never put real data into the local stack.

## 3a. Required `supabase/config.toml` changes vs. CLI defaults
Verified against the defaults generated by `supabase init` (CLI 3.1.0). The defaults do **not** meet the security
requirements, so the committed config overrides them (same values later mirrored in staging/production settings):

| Setting | CLI default | VrtićOS | Requirement |
|---|---|---|---|
| `[api] max_rows` | 1000 | 100 | SR-API-06 |
| `[auth] jwt_expiry` | 3600 s | 900 s (proposal, Q-S10) | SR-SESS-02 |
| `[auth] enable_refresh_token_rotation` | true | true | SR-SESS-02 |
| `[auth.email] otp_length` / `otp_expiry` | 6 / 3600 s | 6 / 600 s | SR-AUTHN-02 |
| `[auth.mfa.totp] enroll_enabled` / `verify_enabled` | false / false | true / true | SR-AUTHN-07 |
| `[auth] enable_signup` | true | false (invitation-only; accounts created by `accept-invitation`) | ADR-0008 |
| `[realtime] enabled` | true | false | SR-API-05 |
| `[api] schemas` | `public, graphql_public` | `public, api` (no `graphql_public`, no `private`) | SR-API-01, SR-TEN-01 |

## 4. Commands (to be implemented as root scripts in Phase 5)
| Script | Does |
|---|---|
| `pnpm setup` | `corepack enable`, `pnpm install --frozen-lockfile`, copy `.env.example` → `.env.local` for both apps |
| `pnpm db:start` | `supabase start` (with registry override if `VRTICOS_DOCKERHUB=1`) |
| `pnpm db:reset` | drop + apply all migrations + run synthetic seed (`supabase db reset`) |
| `pnpm db:test` | pgTAP: catalog checks, permission matrix, NEG-01…15 |
| `pnpm db:types` | regenerate `packages/db-types` |
| `pnpm functions:serve` | `supabase functions serve` (Edge Functions locally) |
| `pnpm dev:admin` | Next.js dev server |
| `pnpm dev:mobile` | `expo start` with `EXPO_PUBLIC_SUPABASE_URL=http://<LAN-IP>:54321` |
| `pnpm demo` | db:start → db:reset → functions:serve → dev:admin + dev:mobile (Turborepo parallel) |
| `pnpm db:stop` | stop containers (data volume kept) |

## 5. Demo for a kindergarten (laptop + phones)
1. Laptop runs `pnpm demo`; phones join the same Wi-Fi (or the laptop's hotspot); mobile app points to the laptop LAN IP.
2. Synthetic seed: kindergartens **"Vrtić Sunce (demo)"** and **"Vrtić Mjesec (demo)"**, 2 facilities, 6 groups,
   ~120 fictional children with generated Croatian names, guardians, educators, a substitute, one access restriction,
   attendance history, absences, announcements, daily entries, conversations. All names generated; no photos.
3. Demo accounts use the reserved `.test` domain (e.g. `odgojiteljica.s1@demo.vrtic.test`) so mail can never be
   delivered; OTP codes are read from Mailpit. Manager accounts enroll TOTP on first login (shows the MFA story).
4. A banner "DEMO — izmišljeni podaci" is shown in both apps when `APP_ENV=demo`.
5. After the presentation: `pnpm db:reset` restores the seed.

## 6. Safety rails
- Seed and reset scripts **refuse to run** unless the DB host is `127.0.0.1`/`localhost` and `APP_ENV` is `local|demo`.
- `.env*` git-ignored except `.env.example`; CI secret scanning (SR-SUP-04).
- Local stack ports bound to localhost by default; for LAN demo only the API port is exposed, on a private network.
- No Sentry DSN, no push credentials, no SMTP credentials in local configuration.
- Never import real exports, spreadsheets or photos from a kindergarten into a local environment (R-37).

## 7. CI parity
GitHub Actions runners have Docker running; the `db` job uses the same `supabase start` + migrations + pgTAP as
locally (technical-architecture.md §7). If the ECR CDN is unreachable from CI, the same registry override applies.

## 8. Troubleshooting
| Symptom | Fix |
|---|---|
| `failed to connect to the docker API` | start Docker (`dockerd` in containers, Docker Desktop elsewhere) |
| image pull `Forbidden` from `cloudfront.net` | `export SUPABASE_INTERNAL_IMAGE_REGISTRY=docker.io` |
| Edge Runtime file-descriptor warning | harmless for local use |
| Phone cannot reach API | use LAN IP, check firewall, same network; Expo Go must reach port 54321 |
| OTP email missing | open Mailpit at :54324 |
